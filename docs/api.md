# rapid.codes API (v1)

This document is the design contract for the v1 API. The machine-readable
OpenAPI spec is generated by FastAPI from the code and served at `/openapi.json`
(interactive docs at `/docs`). If the two ever disagree, that is a bug.

Base URL: `https://rapid.codes`

## Endpoints at a glance

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/v1/links` | Create a short link (or get the existing one for this URL) |
| `GET` | `/{code}` | Redirect to the long URL |

---

## `POST /api/v1/links`

Shortens a URL. Anonymous, no authentication. [Rate limited](#rate-limits).

### Request

```http
POST /api/v1/links HTTP/1.1
Content-Type: application/json

{ "url": "https://example.com/some/very/long/path?x=1" }
```

| Field | Type | Required | Rules |
|---|---|---|---|
| `url` | string | yes | See [URL rules](#url-rules) |

### Responses

**`201 Created`**: a new link was created.

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: https://rapid.codes/aZ3kQ9x

{
  "code": "aZ3kQ9x",
  "short_url": "https://rapid.codes/aZ3kQ9x",
  "url": "https://example.com/some/very/long/path?x=1"
}
```

**`200 OK`**: a link for this URL already existed (D2, D5). Same body, no
`Location` header. Submitting the same URL any number of times always returns
the same code.

| Field | Description |
|---|---|
| `code` | The short code: random Base62 characters (`0-9`, `a-z`, `A-Z`), currently 7 (D15). Clients must not rely on the length. |
| `short_url` | The full short link, ready to share. |
| `url` | The stored URL **after normalization** (D7), which may differ from what was sent, for example `HTTPS://Example.com/a` becomes `https://example.com/a`. |

**Errors**

| Status | `code` | When |
|---|---|---|
| `422` | `validation_error` | Body is missing, not JSON, or `url` is not a string |
| `422` | `invalid_url` | `url` breaks one of the [URL rules](#url-rules). `detail` says which. |
| `422` | `url_disabled` | A link for this URL exists but has been disabled (D11) |
| `429` | `rate_limited` | Too many links created from this IP. See `Retry-After`. |
| `503` | `code_generation_failed` | No free code was found after 3 attempts (D15). Extremely rare; safe to retry. |

### URL rules

Checked in this order. The first failure is reported.

1. At most **2048 bytes** in UTF-8 (D12). Non-ASCII characters count as 2-4 bytes.
2. Parses as an absolute URL with a host.
3. Scheme is `http` or `https`.
4. **No explicit port**, not even `:80` or `:443` (D13).
5. Host is not `rapid.codes` or any subdomain of it (prevents redirect loops).

Then the URL is normalized (D7): scheme and host are lowercased. Nothing else
changes: path, trailing slash, query order, and fragment are kept exactly.

## `GET /{code}`

Redirects to the long URL. This is the endpoint browsers hit.

**`302 Found`**

```http
HTTP/1.1 302 Found
Location: https://example.com/some/very/long/path?x=1
Cache-Control: no-store
```

`302` with `no-store` means every click reaches the server, so a disabled link
stops working immediately and click statistics can be added later (D1).

**Errors**

| Status | `code` | When |
|---|---|---|
| `404` | `not_found` | No link with this code ever existed. Also returned for codes with invalid characters and for reserved words (D9). |
| `410` | `link_disabled` | The link existed but has been disabled, for any reason (D6) |
| `429` | `rate_limited` | Too many redirects, or too many unknown codes, from this IP. See `Retry-After`. |

## Rate limits

Limits apply per client IP address. For IPv6, they apply per `/64` prefix,
because one user typically controls a whole `/64` block (D16).

| Request | Limit |
|---|---|
| `POST /api/v1/links` | 10 per minute |
| `GET /{code}` that redirects | 100 per minute |
| `GET /{code}` that returns `404` | 10 per minute |

The strict `404` limit targets enumeration: someone guessing codes gets mostly
`404` responses, while normal users almost never do. A limited request gets
`429 Too Many Requests` with a `Retry-After` header.

## Errors

All errors use **RFC 9457 Problem Details** (D10) with content type
`application/problem+json`, plus a `code` field that clients can branch on.

```http
HTTP/1.1 422 Unprocessable Content
Content-Type: application/problem+json

{
  "type": "about:blank",
  "title": "Unprocessable Content",
  "status": 422,
  "detail": "URLs with an explicit port are not allowed.",
  "code": "invalid_url"
}
```

| Field | Meaning |
|---|---|
| `type` | Always `about:blank` in v1: the HTTP status says what kind of problem it is, and `code` refines it. |
| `title` | The standard name of the HTTP status. |
| `status` | The HTTP status code, repeated in the body. |
| `detail` | A human-readable explanation of this specific error. For people, not for code. |
| `code` | Machine-readable error identifier. Stable: clients may depend on it. |

`validation_error` responses add an `errors` list with one entry per invalid
field. FastAPI's default validation response has a different shape, so it is
replaced with a custom exception handler.

`429` responses include a `Retry-After` header with the number of seconds to wait.

Unexpected failures return `500` with `code: "internal_error"` and no internal
details (no stack traces, no SQL).

### All error codes

| `code` | Status | Endpoint |
|---|---|---|
| `validation_error` | 422 | `POST /api/v1/links` |
| `invalid_url` | 422 | `POST /api/v1/links` |
| `url_disabled` | 422 | `POST /api/v1/links` |
| `rate_limited` | 429 | any |
| `code_generation_failed` | 503 | `POST /api/v1/links` |
| `not_found` | 404 | `GET /{code}` |
| `link_disabled` | 410 | `GET /{code}` |
| `internal_error` | 500 | any |

---

## Not in v1

Custom aliases, expiration, click statistics, user accounts, and an endpoint
for reading a link's details (`GET /api/v1/links/{code}`).
